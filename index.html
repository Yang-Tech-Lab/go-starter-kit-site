The problem

Every Go API starts the same way: routing, auth, a database, migrations, config, logging, error handling, tests. Done carefully, that is days of boilerplate before you write a single line of your product. Done hastily, it becomes the tech debt you pay for later.

This starter is that foundation, already built and already working — deliberately boring, four layers, one direction of dependencies, no framework magic. You read it in an afternoon and extend it without fighting abstractions.

What's inside

Pure standard-library HTTP

Go 1.22+ net/http routing with method patterns. No web framework to learn, upgrade, or fight. Handlers are plain http.HandlerFuncs.

SQLite out of the box

database/sql + modernc.org/sqlite (pure Go, no cgo). Embedded SQL migrations run automatically on startup.

JWT auth, stdlib crypto

HMAC-SHA256 tokens signed and verified with only the standard library, bcrypt password hashing, and auth middleware for protected routes.

Two working example apps

A shortlink service (create, list, redirect, visit counts) and a notes CRUD — both owner-scoped, showing how the same pattern repeats for any resource.

Production habits included

Env-based config with .env support, structured JSON logging (log/slog), graceful shutdown, /healthz, input validation, and one consistent JSON error envelope.

Tests included

Test suites for auth, handlers, and the store. Run them with make test. Ownership failures return 404, so callers can't probe other users' records.

Four guides, not just code

Architecture, auth design, database (including how to swap to Postgres), and deployment — VPS, Docker, and free-tier notes.

12 SQL exercises

Progressive exercises on the starter's own schema — SELECT, JOINs, aggregates, migrations — with solutions included.

Running in 5 minutes

cp .env.example .env
make test
make run
# Server listens on http://localhost:8080

curl localhost:8080/healthz
curl -X POST localhost:8080/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"ada@example.com","password":"password123"}'

The README walks through the full flow — register, log in, shorten a link, watch visits grow — and shows how to rename the module and add your own resource by copying the notes pattern.

FAQ

What do I need to run it?

Go 1.25 or later — that's it. SQLite is embedded (pure Go driver, no cgo), so there is no database to install. Everything is configured through environment variables; a .env.example is included.

Which framework does it use?

None. It uses Go's standard library net/http with Go 1.22+ routing. If you outgrow the standard mux, the handlers are plain http.HandlerFuncs and move easily to a framework later.

Can I use Postgres instead of SQLite?

Yes, with your own work: handlers depend on small repository interfaces (UserStore, LinkStore, NoteStore), so swapping databases means writing a new implementation, not rewriting handlers. The database guide explains the approach.
